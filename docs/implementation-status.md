# Implementation Status

이 문서는 현재 커밋이 실제로 보장하는 것과, 계획 문서에 남아 있는 다음 목표를 구분한다.

## Current Reality

- Storage adapter: local SQLite database plus filesystem object storage.
- Object properties: SQLAlchemy `JSON` columns, not PostgreSQL `JSONB`.
- Ingestion: CSV upload and the application-level connector snapshot commit path are implemented. The current connector snapshot path is backed by the local/fake `ConnectorAdapter`; a production PostgreSQL snapshot adapter remains future work.
- CSV upload size: default local limit is 50 MiB via `FOUNDRY_LITE_MAX_CSV_UPLOAD_BYTES`.
- Preconditions: `safeExpression` supports a small safe subset only:
  - `object.status in ['PENDING', 'REVIEW']`
  - `object.status == 'PENDING'`
- Writeback: `mock_erp_simulator` records simulated before-commit writeback rows. It does not call an external ERP.
- Security default: API requests authenticate through an explicit `AuthProvider` port chosen by `FOUNDRY_LITE_AUTH_PROFILE` at the composition root. The local/default `HeaderTrustAuthProvider` still reads `X-Tenant-ID`/`X-User-ID`/`X-Roles` headers verbatim, but `FOUNDRY_LITE_RUNTIME_PROFILE=production` fails startup if `header-trust` or `demo` auth is selected. CLI and demo scripts continue to use an explicit demo admin context; a real JWT/OIDC adapter remains future work.
- Security/Governance: `PolicyService` defines the v1 role matrix for `admin`, `data_engineer`, `ops_manager`, `viewer`, and `finance`; dataset/object reads, dataset writes, ontology activation, action execution, materialization, and operations retry go through application-layer permission checkpoints. Object responses and link traversal apply masking to the Order margin property for non-`finance`/non-`admin` users. Permission denials on mutation/activation/retry paths write `permission.denied` audit evidence with `decision=deny`. Tenant isolation is enforced at repository/API query boundaries, and PostgreSQL schema bootstrap applies RLS policies through `apply_postgres_rls` for tenant-scoped tables plus `dataset_schemas`. `set_postgres_tenant_context` sets the DB session tenant, and `test_postgres_rls_hides_dataset_and_object_rows_between_tenants` proves a non-owner DB role sees only its own dataset/object rows, sees no rows without tenant context, and cannot insert another tenant's object row.
- OSDK-lite: `scripts/generate_sdk_ts.py` reads the active supply-chain ontology and writes generated TypeScript SDK outputs to `packages/sdk-ts/src/generated.ts` plus the browser-ready `apps/web/generated-sdk.js`. Both outputs now export the same `SDK_CLIENT_SURFACE` generated from the shared ontology client surface, and `test_sdk_package_and_browser_outputs_share_client_surface` blocks object/action method drift between package and browser SDKs. The generated client exposes typed object get/query calls, typed action apply payloads, and helper functions for idempotency keys and expected object versions. `examples/sdk-demo.ts` demonstrates a typed Order query and action apply flow, the Object Explorer now imports the browser SDK for object load and ApproveOrder action execution, and `quality:sdk-generated` blocks stale generated outputs when ontology apiName contracts drift.
- Object sets: static and dynamic saved object sets are implemented through core service, HTTP API, CLI, and Object Explorer list/create controls. Private owner visibility and temporary expiry are enforced.
- Source evidence navigation: `GET /api/objects/{object_type}/{object_id}?explain=true`, `flite object get <type> <id> --explain`, and the web Source Run control expose `sourceRunChain` links with `runType`, `runId`, status, relation, and operation detail endpoint path so an operator can move from object detail to source index/producer run detail without opening the database.
- Operations surface: `flite operations runs --type/--status/--since/--until`, `GET /api/operations/runs?runType=&status=&since=&until=`, and the web Operations panel expose tenant-scoped sync, transform, index, action, materialization, outbox, DLQ, and audit rows with operator filters. `flite operations run <type> <id>`, `GET /api/operations/runs/{run_type}/{run_id}`, and the web Run Detail control return the selected row, status, normalized error message, correlation id, key references, a human-readable `investigation` summary with suggested next actions, related outbox/audit/object-edit/writeback rows, and lineage edges so an operator can investigate basic failures without opening the database. `flite transform retry <transform-run-id>`, `POST /api/operations/runs/transform/{run_id}/retry`, and the web Retry Failed Transform control retry a failed transform run with the original `input_versions` captured on that run, then write `transform.run.retry_requested` audit evidence linking the failed run to the new run. `flite index replay <object-type>`, `POST /api/operations/index/{object_type}/replay`, and the web Replay Index control rebuild an object index from the latest source dataset version and publish a fresh index run for operator follow-up. `flite index replay-run <index-run-id>`, `POST /api/operations/runs/index/{run_id}/replay`, and the web Replay Failed Index control replay a failed index run with its original `source_ref.dataset_version_id` and record `source_ref.replay_of_run_id` on the new run. `flite outbox retry <dead-letter-event-id>`, `POST /api/operations/dead-letter-events/{event_id}/retry`, and the web Retry DLQ control requeue an existing source outbox event from DLQ back to `pending`, reset attempts, remove the DLQ row, write audit evidence, and for `materialization.requested` payloads immediately run the named materialization with `materializationResult` evidence. Broader failed sync/action/materialization-run replay workflows are still future work.
- Sprint 36A operational hardening: concurrent same-key action idempotency now turns database unique races into replay through `ActionRepository.insert_action_run_or_get_existing`. Dataset commit locks the dataset row before version allocation, maps duplicate metadata inserts to `DatasetVersionConflictError`, and removes already-promoted artifacts through `DatasetStorageAdapter.delete_committed_version` while preserving `orphan_cleanup` evidence. Object Query delegates tenant/object type/filter/order/cursor/limit to `ObjectReadRepository.query_active_object_rows`, uses opaque `oqc1.` cursor tokens with query-shape checksum, applies ontology/property metadata casts for property sorting, adds `object_id` as the stable tie-breaker, and caps page size at 500; dynamic Object Set membership follows the same cursor paging. ## Refactor Pointers

These are known design debts that are currently gated (so they cannot regress) but
should be paid down on a planned timeline. They are not bugs; they are deliberate
intermediate states.

- **Application Service canonicalization.**
  `FoundryLiteCore` no longer composes service capabilities through Python
  multiple inheritance. It is a thin Facade with explicit public forwarders,
  while `CoreServices` constructs `ActionService`, Dataset service group,
  Object service group, Transform, Ontology, Materialization, Runtime, and Demo
  services with service-specific dependency injection. A service receives only
  the `CoreDependencies` fields listed in its `required_dependencies`; for
  example, `ActionService` receives `engine`, `policy`, and `action_repository`,
  not storage or transform adapters. A service also receives only the
  collaborator services listed in its `required_collaborators`; for example,
  `ActionService` receives runtime, ontology, object-record, and object-indexing
  collaborators, not all 16 services. Cross-service helper access now uses
  explicit collaborator attributes such as `runtime_service._audit(...)` rather
  than `__getattr__` method lookup. These rules are held in check by static gates:
  `check_service_dependencies.py`, `check_service_call_graph.py`, Tach, AST-grep,
  and the application-size cap. This keeps the
  public API stable while removing facade-level MRO risk before Workflow /
  Stream / Search / Connector / Auth boundaries are extracted.
- **Remaining Facade compatibility debt.**
  The flat service method registry and `FoundryLiteCore.__getattr__` /
  `FoundryLiteCore.__setattr__` monkeypatch bridge have been removed. The
  remaining compatibility cost is the explicit public forwarder list in
  `FoundryLiteCore`, which keeps API/CLI/test entrypoints stable while services
  continue to evolve independently.

## Quality Signal Boundaries

- Branch coverage is the main behavior gate.
- Public callable coverage means "a public callable was executed at least once"; it is not a substitute for branch/path coverage.
- CI enforces `0` `core._...` private facade references in tests. Some lower-level tests still target service/helper modules directly to pin failure edges, but the public facade no longer exposes or forwards private helper methods.
