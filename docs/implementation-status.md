## Current Reality

- Storage adapter: local SQLite database plus filesystem object storage by default; optional MinIO/S3-compatible object storage is available through `S3DatasetStorageAdapter` and the `s3-storage` adapter profile. The second infra ratchet adds `IcebergDatasetStorageAdapter` and the `iceberg` profile: each dataset version is one Iceberg table snapshot (pinned by `snapshot_id`) with data/metadata in object storage and a SQL catalog tracking the pointer, covered by `quality:iceberg` against MinIO/Testcontainers. Iceberg now keeps Foundry sidecar manifests beside the table data so commit-time branch/created_at and real object-byte hashes are recoverable on read; duplicate-version guard catalog timeouts fail closed as retryable adapter failures. Dataset preview reads use the storage-port `preview_file_paths(...)` boundary, so Iceberg preview validates the pinned snapshot file list and downloads verified manifest data files directly instead of materializing the whole snapshot through `to_arrow()` for ordinary bounded previews. The third infra ratchet adds `SparkComputeAdapter` and the `spark` compute profile (selected independently of storage via `FOUNDRY_LITE_COMPUTE_PROFILE`): Spark runs CSV ingest and SQL transforms on local parquet that the engine materializes from any storage profile, output commits through the dataset transaction protocol, same-session concurrent transforms use per-run temp views, and Spark row-batch CSV staging preserves quoted JSON/CDC strings, covered by `quality:spark`. The composition ratchet is now explicit: `quality:infra-composition` boots `adapter_profile=iceberg` with `FOUNDRY_LITE_COMPUTE_PROFILE=spark` against a MinIO warehouse so Spark reads Iceberg-on-S3 pinned inputs and commits output back to Iceberg-on-S3, including a failure→abort proof. The same composition gate now covers Debezium CDC on the active stack: Debezium-normalized events archive into an Iceberg-on-S3 changelog through Spark, replay into CDC object indexing, skip a stale post-delete update, materialize `ops.order_current`, and prove archive writer failure leaves no raw CDC dataset version. `quality:distributed-control-plane` now groups the PostgreSQL metadata control-plane plus MinIO/S3 + Iceberg + Spark failure-abort proof, live Kafka broker archive worker proof, PostgreSQL-backed parallel Kafka worker cursor-CAS duplicate-commit proof, Temporal product workflow proof, workflow ledger CAS, dataset commit CAS, and Record DLQ replay lease fencing. Genuinely distributed Spark executor/cluster failure modes still need a real cluster and are deferred. CI now acts as an automated reviewer: proof-matrix, source-of-truth, and operator-evidence contract gates read the single `docs/infra-tricky-matrix.json` and emit root-cause-style failures with suggested files; `quality:documentation-map` keeps the documentation operating map, README document index, core source-of-truth rows, and cross-check commands from drifting; these gates run in the `ci:gate:runtime` or `ci:gate:static` lanes for PR feedback and in `ci:gate:release` for push/tags/dispatch evidence (`release.yml`, heavier perf smokes + uploaded artifacts).
- Local fault rehearsal: `pnpm fault:local` and `pnpm fault:local:stress` are explicit, non-CI operator drills that write `artifacts/operations/local_fault_lab.json`. The stress profile boots a Spark `local-cluster[2,1,512]`, kills a real executor JVM during a job, starts live Kafka plus PostgreSQL through Testcontainers, drives an 8-worker same-offset cursor-CAS storm, and restarts a bounded continuous archive worker over 80 broker events. The same evidence deliberately records two boundaries as `boundary_not_locally_proven`: managed Temporal multi-node failover and Kafka broker commit-unknown/rebalance callbacks still require infrastructure the current local worker architecture does not yet use.
- Object properties: SQLAlchemy `JSON` columns, not PostgreSQL `JSONB`.
- Commit-point risk tracking: [Commit-Point Risk Register](./commit-point-risk-register.md) now separates "feature works" from "the durable commit-point invariant is proven." Materialization watermarks have been hardened for the current MVP path: `action_log` pins `completed_at` plus `action_run_id`, and `object_snapshot` pins `active_index_version` plus tenant-scoped `object_change_sequence` while capturing output rows at run start. Object changes now append `object_record_versions`, so an old `object_snapshot` run can replay its stored watermark after later in-place object updates and still produce the original row hash/state. This prevents late-committed actions from being skipped, keeps failed action runs out of successful `ops.action_log` materialization rows, keeps same-cursor `action_log` reruns from duplicating rows inside the output, prevents a mid-run action from partly entering the same `ops.order_current` output, and makes old snapshot watermarks durable enough for replay evidence. `action_log` source reads now go through `MaterializationRepository.action_log_rows_at_watermark(...)`, so tenant/status/watermark filtering and object-edit patch joining happen at the repository query boundary instead of loading all action and edit rows into application memory first. Materialization metadata/outbox/lineage failure after storage promotion removes the promoted artifact, exposes no `materialization.completed` event for the failed run, and lets a same-cursor retry commit exactly one output version. Dataset/storage split-brain protection has also been hardened for the local MVP and MinIO/S3-compatible paths: storage promotion followed by DB metadata failure removes the promoted version artifact, FAILED sync runs keep `orphan_cleanup` evidence, committed versions with missing manifest/data files raise `committed_version_storage_missing`, local and S3 adapters verify manifest URI, byte size, and content hash after write, S3 partial multipart timeout cleanup prevents a partial object from becoming a committed version, same-version retry creates exactly one manifest/data pair, and S3 storage failures surface `adapterFailure` evidence in Operations. Dataset transaction finalization now rejects stale `SNAPSHOT` base versions before storage promotion and marks a transaction row committed only from `OPEN`, so a closed transaction cannot be re-committed as if it were still writable. Transform output/lineage atomicity now uses the dataset finalization boundary for post-commit metadata: if lineage insertion fails after output storage promotion, the promoted artifact is removed, no output version or lineage edge is served, and the transform run is marked `FAILED` with cleanup evidence. Compute-stage transform failure also deletes transaction staging artifacts, so a DuckDB OOM-like failure after writing a partial staged output leaves no committed output version and no partial staged file. Transform runs now store a `definition_snapshot` with the SQL template, input/output definition, checks, and SQL hash; failed-run retry replays that stored snapshot instead of reading the latest mutable transform definition. SQL transform execution rejects raw filesystem read functions such as DuckDB CSV path reads; transforms must use declared dataset inputs through the `{{ input('namespace.name') }}` template boundary. Python transforms are fail-closed at registration until a sandboxed SDK input/output abstraction exists, so user Python code cannot receive raw storage paths or credentials today. Materialization execution now treats unknown `materialization_type` values as validation errors instead of falling through to the `object_snapshot` implementation. Stream/REST cursor commit-point proof now covers the local failure-injection path: if a stream batch or REST page is read but dataset writing fails, retry resumes from the last committed offset/cursor rather than the failed attempt's next cursor. Stream archive commit also rechecks the committed stream cursor after taking the dataset version-allocation lock, so parallel PostgreSQL-backed Kafka workers that read the same offset cannot both create committed dataset versions for that offset; the losing worker receives `ConflictDetected` and leaves one committed version. Action idempotency request-fingerprint proof now covers the current action path: same-key replay requires the same canonical request fingerprint, while same-key/different-body reuse returns `ConflictDetected` and leaves `action.run.idempotency_conflict` audit evidence. Action target invariants now reject requests whose object type differs from the action's declared target before idempotency-key reservation, reject corrupted target records whose internal object-type id differs before action-run insertion, and store the target API name from the action definition rather than the caller payload. Action commit atomicity proof now covers the current internal DB action path: failures at object mutation/edit/status/outbox/audit boundaries roll back together and no partial action evidence survives; the action idempotency winner insert now uses conflict-ignore semantics instead of a savepoint that could escape outer rollback on SQLite. Runtime outbox inserts now convert only the expected tenant/event/idempotency duplicate into idempotent replay; unrelated DB integrity errors are re-raised. Remaining gaps: S3 Parquet footer-specific validation can be added beyond byte/hash read-back, full Kafka group rebalance revoke fencing and broker commit-unknown reconciliation still need failure injection, REST page-number sources still need explicit non-replayable labeling or rejection, and vendor-backed external writeback still needs real remote lookup, compensation worker execution, persistent reconciliation queue, and approval flow beyond the current simulated/operator-resolve S53 slices.

## Refactor Pointers

These are known design debts that are currently gated (so they cannot regress) but
should be paid down on a planned timeline. They are not bugs; they are deliberate
intermediate states.

- **Application Service canonicalization.**
  `FoundryLite` no longer composes service capabilities through Python
  multiple inheritance. It is a platform root that exposes one thin facade per
  bounded context (`DatasetWorkspace`, `TransformPipeline`, `OntologyRegistry`,
  `ObjectStore`, `ActionGateway`, `MaterializationRunner`, `OperationsConsole`,
  `SupplyChainDemo`), each holding explicit public forwarders,
  while `CoreServices` constructs `ActionService`, Dataset service group,
  Object service group, Transform, Ontology, Materialization, Runtime, and Demo
  services with service-specific dependency injection. A service receives only
  the `CoreDependencies` fields listed in its `required_dependencies`; for
  example, `ActionService` receives `engine`, `policy`, and `action_repository`,
  not storage or transform adapters. A service also receives only the
  collaborator services listed in its `required_collaborators`; for example,
  `ActionService` receives runtime, ontology, object-record, and object-indexing
  collaborators, not all 16 services. Cross-service helper access now uses
  explicit collaborator attributes such as `runtime_service._audit(...)` rather
  than `__getattr__` method lookup. These rules are held in check by static gates:
  `check_service_dependencies.py`, `check_service_call_graph.py`, Tach, AST-grep,
  and the application-size cap. This keeps the
  public API stable while removing facade-level MRO risk before Workflow /
  Stream / Search / Connector / Auth boundaries are extracted.
- **Remaining Facade compatibility debt.**
  The flat service method registry and `FoundryLite.__getattr__` /
  `FoundryLite.__setattr__` monkeypatch bridge have been removed. The
  remaining compatibility cost is the explicit public forwarder list spread
  across the bounded-context sub-facades, which keeps API/CLI/test entrypoints
  stable while services continue to evolve independently.

## Quality Signal Boundaries

- Branch coverage is the main behavior gate.
- Public callable coverage means "a public callable was executed at least once"; it is not a substitute for branch/path coverage.
- CI enforces `0` `core._...` private facade references in tests. Some lower-level tests still target service/helper modules directly to pin failure edges, but the public facade no longer exposes or forwards private helper methods.
