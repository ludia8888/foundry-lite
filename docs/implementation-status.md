# Implementation Status

**Status:** Current implementation boundary / source of truth for current, partial, and future claims
**Audience:** Maintainers, reviewers, frontend planners, and operators checking what the current checkout truly proves

이 문서는 현재 커밋이 실제로 보장하는 것과, 계획 문서에 남아 있는 다음 목표를 구분한다. 스프린트 체크박스별 PR, merge commit, 테스트, 품질 게이트 근거는 [Sprint Evidence Ledger](./sprint-evidence-ledger.md)를 따른다.

현재 proposal/release 검토 정책은 검토 담당 배정, 사람 Authorization Code principal, 위젯의 명시적 one-time 확인, exact fingerprint와 stale 차단을 요구한다. 작성자와 검토자의 `subject`·OAuth session·MCP session이 서로 달라야 한다는 조건은 제거됐으므로, 같은 사용자가 자신의 Ontology/Pipeline 제안을 self-claim하고 승인할 수 있다. 외부 GitHub ruleset이 별도 리뷰어를 요구하면 그 provider 규칙은 독립적인 추가 조건이다.

## Refactor Pointers

These are known design debts that are currently gated (so they cannot regress) but
should be paid down on a planned timeline. They are not bugs; they are deliberate
intermediate states.

- **Application Service canonicalization.**
  `FoundryLite` no longer composes service capabilities through Python
  multiple inheritance. It is a platform root that exposes one thin facade per
  bounded context (`DatasetWorkspace`, `TransformPipeline`, `OntologyRegistry`,
  `ObjectStore`, `ActionGateway`, `MaterializationRunner`, `OperationsConsole`,
  `SupplyChainDemo`), each holding explicit public forwarders,
  while `CoreServices` constructs Action, Dataset, Object, Transform, Ontology,
  Materialization, Runtime, and Demo service groups or focused services
  services with service-specific dependency injection. A service receives only
  the `CoreDependencies` fields listed in its `required_dependencies`; for
  example, `ActionApplyService` receives `engine`, `policy`, and
  `action_repository`, not storage or transform adapters. A service also
  receives only the collaborator services listed in its `required_collaborators`;
  for example, `ActionApplyService` receives writeback, runtime, ontology,
  object-record, object-indexing, and OSDK-scope collaborators, not all
  services. Cross-service helper access now uses
  explicit collaborator attributes such as `runtime_service._audit(...)` rather
  than `__getattr__` method lookup. These rules are held in check by static gates:
  `check_service_dependencies.py`, `check_service_call_graph.py`, Tach, AST-grep,
  and the application-size cap. This keeps the
  public API stable while removing facade-level MRO risk before Workflow /
  Stream / Search / Connector / Auth boundaries are extracted.
- **Remaining Facade compatibility debt.**
  The flat service method registry and `FoundryLite.__getattr__` /
  `FoundryLite.__setattr__` monkeypatch bridge have been removed. The
  remaining compatibility cost is the explicit public forwarder list spread
  across the bounded-context sub-facades, which keeps API/CLI/test entrypoints
  stable while services continue to evolve independently.

- Transform bounded-context split: Transform is now split into pure domain rules plus explicit application use-case services for definition, run, scheduler, graph, and the current partial transform row-DLQ replay path. `TransformService` remains as the compatibility entrypoint for `foundry.transforms.*`, API callers, and SDK-facing contracts, while `TransformServices` registers the subservices in the dependency/collaborator graph so quality gates can inspect each responsibility separately. Action bounded-context split is also current: `ActionService` remains the compatibility entrypoint for `foundry.actions.*`, API callers, Operations writeback controls, and SDK-facing contracts, while `ActionServices` registers apply, validation, and writeback use-case services separately.
- Domain Rule Kernel split: common platform rules for idempotency replay/conflict, terminal state transitions, write-traffic blocking, evidence redaction, and OSDK resource-scope vocabulary are now in `libs/foundry_lite/domain/platform`. Object CDC ordering/stale-event/tombstone rules, object indexing duplicate-source/shadow-validation/source-missing/conflict decisions, backup/restore resume approval plus artifact restore eligibility rules, dataset quality policy/default-primary-key rules, and Ontology migration compatibility/reindex-contract rules now have focused domain modules as well. Services still own transactions, repositories, audit, outbox, and external adapters; they call domain rules instead of re-encoding those decisions inline.
- Runtime evidence boundary: `RuntimeEvidenceService` now owns the shared audit/outbox/lineage/run-relation/error-payload/write-traffic helper boundary. `RuntimeService` remains the Operations read/retry compatibility entrypoint and delegates evidence writes to that internal boundary without adding a new public service-call graph level.
- ObjectIndexing bounded-context split: object indexing is now split into a stable compatibility entrypoint plus explicit CDC, rebuild, source-link, shadow promotion, record-mutation/evidence, and ontology-reindex use-case services. Other application services no longer depend on the compatibility entrypoint for merge/rebuild work; they call the focused collaborator they actually need. Object indexing mixins have been removed from the `quality:no-service-mixin-growth` allowlist.
- BackupRestore bounded-context split: backup/restore is now split into a stable compatibility entrypoint plus explicit preflight, restore-mode, artifact creation, artifact verification, historical artifact execution, and validation use-case services. Backup/restore application mixins have been removed from the `quality:no-service-mixin-growth` allowlist, while restore resume and artifact eligibility decisions live in `domain/backup_restore` with direct tests.
- DatasetQuality bounded-context split: dataset quality is now split into a stable compatibility entrypoint plus explicit API, contract-definition, and commit-time runtime services. Data-quality warning/blocking/default-check decisions live in `domain/dataset/quality`, while transaction, repository, audit, and Operations evidence remain in application services. Dataset quality API/contracts mixins have been removed from the `quality:no-service-mixin-growth` allowlist.
- Ontology bounded-context split: ontology is now split into a stable compatibility entrypoint plus explicit activation/import, active-catalog, lookup, and object-reindex-contract services. Ontology migration compatibility, SDK-breaking classification, deterministic object reindex operation keys, and reindex contract completion payload rules live in `domain/ontology`, while activation transactions, repository reads/writes, audit, and outbox remain in application services. Ontology reindex contract mixin debt has been removed from the `quality:no-service-mixin-growth` allowlist.
- Mixin debt boundary: `OsdkApplicationService` is now a thin entrypoint over explicit client, scope, SDK, and idempotency use-case services. New service/facade `*Mixin` growth is blocked by `quality:no-service-mixin-growth`, and new domain rule/specification files require direct tests through `quality:domain-rule-tests`. Remaining allowlisted mixin debt is runtime observability and Operations Console backup compatibility; those are follow-up refactor targets, not current feature gaps.

## Quality Signal Boundaries

- Branch coverage is the main behavior gate.
- Public callable coverage means "a public callable was executed at least once"; it is not a substitute for branch/path coverage.
- CI enforces `0` `core._...` private facade references in tests. Some lower-level tests still target service/helper modules directly to pin failure edges, but the public facade no longer exposes or forwards private helper methods.
