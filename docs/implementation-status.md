# Implementation Status

이 문서는 현재 커밋이 실제로 보장하는 것과, 계획 문서에 남아 있는 다음 목표를 구분한다. 스프린트 체크박스별 PR, merge commit, 테스트, 품질 게이트 근거는 [Sprint Evidence Ledger](./sprint-evidence-ledger.md)를 따른다.

## Current Reality

- Storage adapter: local SQLite database plus filesystem object storage.
- Object properties: SQLAlchemy `JSON` columns, not PostgreSQL `JSONB`.
- Commit-point risk tracking: [Commit-Point Risk Register](./commit-point-risk-register.md) now separates "feature works" from "the durable commit-point invariant is proven." Materialization watermarks have been hardened for the current MVP path: `action_log` pins `completed_at` plus `action_run_id`, and `object_snapshot` pins `active_index_version` plus tenant-scoped `object_change_sequence` while capturing output rows at run start. Object changes now append `object_record_versions`, so an old `object_snapshot` run can replay its stored watermark after later in-place object updates and still produce the original row hash/state. This prevents late-committed actions from being skipped, keeps failed action runs out of successful `ops.action_log` materialization rows, keeps same-cursor `action_log` reruns from duplicating rows inside the output, prevents a mid-run action from partly entering the same `ops.order_current` output, and makes old snapshot watermarks durable enough for replay evidence. Materialization metadata/outbox/lineage failure after storage promotion removes the promoted artifact, exposes no `materialization.completed` event for the failed run, and lets a same-cursor retry commit exactly one output version. Dataset/storage split-brain protection has also been hardened for the local MVP path: storage promotion followed by DB metadata failure removes the promoted version directory, FAILED sync runs keep `orphan_cleanup` evidence, committed versions with missing manifest/data files raise `committed_version_storage_missing`, and the local adapter verifies manifest URI, byte size, and content hash after write. Transform output/lineage atomicity now uses the dataset finalization boundary for post-commit metadata: if lineage insertion fails after output storage promotion, the promoted artifact is removed, no output version or lineage edge is served, and the transform run is marked `FAILED` with cleanup evidence. Compute-stage transform failure also deletes transaction staging artifacts, so a DuckDB OOM-like failure after writing a partial staged output leaves no committed output version and no partial staged file. SQL transform execution rejects raw filesystem read functions such as DuckDB CSV path reads; transforms must use declared dataset inputs through the `{{ input('namespace.name') }}` template boundary. Python transforms are fail-closed at registration until a sandboxed SDK input/output abstraction exists, so user Python code cannot receive raw storage paths or credentials today. Stream/REST cursor commit-point proof now covers the local failure-injection path: if a stream batch or REST page is read but dataset writing fails, retry resumes from the last committed offset/cursor rather than the failed attempt's next cursor. Action idempotency request-fingerprint proof now covers the current action path: same-key replay requires the same canonical request fingerprint, while same-key/different-body reuse returns `ConflictDetected` and leaves `action.run.idempotency_conflict` audit evidence. Action commit atomicity proof now covers the current internal DB action path: failures at object mutation/edit/status/outbox/audit boundaries roll back together and no partial action evidence survives; the action idempotency winner insert now uses conflict-ignore semantics instead of a savepoint that could escape outer rollback on SQLite. Remaining gaps: production S3-like adapters still need multipart/partial-object and cleanup-reachability proofs, stream live-broker rebalance/commit-unknown edges need failure injection, REST page-number sources still need explicit non-replayable labeling or rejection, and real external writeback success followed by local failure still needs `COMPENSATION_REQUIRED`/reconciliation design.
- Ingestion: CSV upload and the application-level connector snapshot commit path are implemented. Connector ingest now includes the local/fake `ConnectorAdapter`, `RestPullConnectorAdapter` with auth/cursor pagination/rate-limit error handling, and `POST /api/connectors/webhooks/{connector_name}/{resource_name}` with timestamp-bound HMAC signature verification via `FOUNDRY_LITE_WEBHOOK_SIGNING_KEY` and append dataset commits. REST connector URLs default to public HTTP(S) targets only: localhost, private, link-local, internal, and metadata host targets are rejected unless `allow_private_network=True` is explicitly set for a local harness. REST cursor resume state is durable at the dataset transaction layer: committed connector syncs persist `dataset_transactions.metadata.connectorCursor`, the next sync uses that cursor by default when the caller does not provide one, and a failed page write cannot advance the durable cursor to the failed attempt's next page. Webhook duplicate delivery is idempotent for the same event id: `X-Foundry-Lite-Event-ID` or a deterministic payload-derived id is stored in `dataset_transactions.metadata.webhookEvent`, and a repeat delivery replays the existing committed version instead of appending another row/version. Webhook signatures include the request timestamp in the signed payload, and stale timestamps outside the replay window are rejected before append while leaving deny audit evidence. Stream archive ingest now includes a local/fake Kafka-compatible `StreamAdapter` proof through `DatasetWorkspace.archive_stream_events`, `StreamArchiveConfig`, APPEND dataset transactions, `dataset_transactions.metadata.streamCursor` checkpoint metadata, topic/partition/offset-derived event ids, `foundry_lite_stream_archive_lag_events`, and FAILED sync-run error trace evidence for writer failures. A failed archive write cannot advance the durable offset beyond the last committed dataset transaction. A production-compatible `KafkaStreamAdapter` and `foundry_lite_worker.stream_archive` one-shot worker now read broker-shaped messages through the same application boundary without direct dataset DB/storage writes; `StreamArchiveWorkerConfig.request_context` rejects a blank tenant id before worker writes can run, and `tests/integration/test_kafka_live_broker_stream_archive.py` proves the broker path against a live Kafka-compatible broker through Testcontainers. Debezium CDC now has both a fast adapter/archive proof and a live source proof: `DebeziumPostgresStreamAdapter` normalizes PostgreSQL CDC insert/update/delete envelopes into `op`, `pk`, `before`, `after`, and `ordering`; `StreamArchiveConfig(schema_strategy="cdc_envelope_json")` archives those events into raw changelog datasets with previewable `pk_json` and `ordering_json` fields; `tests/integration/test_debezium_live_cdc.py` boots Kafka, logical-replication PostgreSQL, and Debezium Connect so `public.orders` insert/update/delete events are read from a real CDC topic and committed through the worker. CDC object indexing now supports optional ontology `backing.cdc` source mappings, `ObjectStore.index_cdc_events`, batch-rebuild-free CDC base patch upsert, `source_deleted` tombstones, duplicate/stale ordering skips, query/materialization tombstone exclusion consistency, fail-closed primary-key update rejection, `cdc_incremental` index runs, and `object.changed` outbox trigger evidence. CDC adapter read failures now create FAILED sync runs with Debezium adapter failure payloads in Operations. Production connector registry/config persistence, background retry workers, broader SaaS connector adapters, deployment-specific Redpanda profile packaging, and a continuously running CDC object-indexing worker remain future work.
- Object index reindexing: `ObjectStore.shadow_reindex` can build a shadow object index namespace, validate count/hash against the active baseline, replay action edit properties into the shadow rows, switch the active serving pointer through the object-type-level `object_index_versions.active_index_version` registry, and keep failed validation from replacing the previous active index. Row-level `index_version`/`is_active` flags still mark which object/link rows are served, but the active version is no longer inferred only from rows, so an object type with `0` rows can still preserve `index_run_*` as the version CDC/search workers should target. Shadow promotion uses a compare-and-swap check against the previously validated active version: if another switch wins first, the later switch fails instead of silently overwriting the pointer. Object Query cursor tokens now include the serving `active_index_version`; if a user fetches page 1 before shadow promotion and asks for page 2 after promotion, the cursor is rejected instead of mixing old/new index pages into duplicate or missing rows. The pointer row id is unique per insert attempt, while the conflict target remains the natural pointer key `tenant_id` plus `object_type_id`; this prevents concurrent first pointer creation from escaping the upsert path through a primary-key-only collision. A full reindex over the active index version is now idempotent: when the source dataset version, base patch, and merged properties are unchanged, the reindex skips the per-object update so it does not bump `object_version` or emit a spurious `object.changed` event, which keeps a held `expectedObjectVersion` valid after a replay. Object read, link read, object set membership, and materialization reads filter to active rows. `quality:shadow-reindex` plus `tests/integration/test_cdc_object_indexing.py` prove the local/fake, SQLite, and Postgres repository contracts, success/failure integration flows, the zero-row CDC follow-up case through `test_empty_shadow_reindex_persists_active_pointer_for_next_cdc_insert`, stale pointer rejection through `test_object_index_repository_contract_rejects_stale_shadow_pointer_switch`, active-index cursor rejection through `test_shadow_reindex_alias_switch_cursor_version_safe`, and a real PostgreSQL concurrent first-pointer race through `test_object_index_repository_contract_concurrent_first_pointer_switch_has_one_winner`. `VERIFY-ACTIVE-INDEX-POINTER-FLAKE` repeats that race `10` times against PostgreSQL to prove the old primary-key-vs-natural-key race is stable. API/CLI/Web operator controls for starting this shadow path are not yet exposed beyond the core facade.
- Search projection: `SearchIndexAdapter` now includes ontology-derived `SearchIndexMapping`, full-text `SearchQuery`, document id listing for drift checks, and local/fake/Elasticsearch-compatible adapter contracts. `ElasticsearchAdapter` is optional behind `foundry-lite[elasticsearch]` and the `FOUNDRY_LITE_SEARCH_PROFILE=elasticsearch` composition-root switch, while object store remains the source of truth. The API object query payload `search` field and `ObjectStore.query(..., search_text=...)` route searchable property full-text requests through the search adapter, then re-read active object records for masking and stale/orphan protection. Search hits expose the search projection version separately from the current object version, so a stale hit can be shown as stale while action entry still uses the fresh object-store state. Search adapter upserts are version guarded: a retry of an older `object.changed` document cannot overwrite a newer projection document in the local/fake/Elasticsearch-compatible profiles. `ObjectStore.consume_search_change` / `flite index consume-search-change` consume an `object.changed` payload for one object, and `ObjectStore.rebuild_search` / `flite index rebuild-search` rebuild the search projection and report `missingDocumentIds` / `orphanDocumentIds`. `quality:search-indexing` covers full-text search, object edit sync, rebuild count parity, orphan detection, and search-adapter failure fallback for get/basic filters; `VERIFY-SHADOW-SEARCH-PROJECTION-EDGES` adds stale-document no-overwrite and search-hit object-store refetch proof. Live Elasticsearch cluster deployment and managed operations remain future operational work.

## Refactor Pointers

These are known design debts that are currently gated (so they cannot regress) but
should be paid down on a planned timeline. They are not bugs; they are deliberate
intermediate states.

- **Application Service canonicalization.**
  `FoundryLite` no longer composes service capabilities through Python
  multiple inheritance. It is a platform root that exposes one thin facade per
  bounded context (`DatasetWorkspace`, `TransformPipeline`, `OntologyRegistry`,
  `ObjectStore`, `ActionGateway`, `MaterializationRunner`, `OperationsConsole`,
  `SupplyChainDemo`), each holding explicit public forwarders,
  while `CoreServices` constructs `ActionService`, Dataset service group,
  Object service group, Transform, Ontology, Materialization, Runtime, and Demo
  services with service-specific dependency injection. A service receives only
  the `CoreDependencies` fields listed in its `required_dependencies`; for
  example, `ActionService` receives `engine`, `policy`, and `action_repository`,
  not storage or transform adapters. A service also receives only the
  collaborator services listed in its `required_collaborators`; for example,
  `ActionService` receives runtime, ontology, object-record, and object-indexing
  collaborators, not all 16 services. Cross-service helper access now uses
  explicit collaborator attributes such as `runtime_service._audit(...)` rather
  than `__getattr__` method lookup. These rules are held in check by static gates:
  `check_service_dependencies.py`, `check_service_call_graph.py`, Tach, AST-grep,
  and the application-size cap. This keeps the
  public API stable while removing facade-level MRO risk before Workflow /
  Stream / Search / Connector / Auth boundaries are extracted.
- **Remaining Facade compatibility debt.**
  The flat service method registry and `FoundryLite.__getattr__` /
  `FoundryLite.__setattr__` monkeypatch bridge have been removed. The
  remaining compatibility cost is the explicit public forwarder list spread
  across the bounded-context sub-facades, which keeps API/CLI/test entrypoints
  stable while services continue to evolve independently.

## Quality Signal Boundaries

- Branch coverage is the main behavior gate.
- Public callable coverage means "a public callable was executed at least once"; it is not a substitute for branch/path coverage.
- CI enforces `0` `core._...` private facade references in tests. Some lower-level tests still target service/helper modules directly to pin failure edges, but the public facade no longer exposes or forwards private helper methods.
