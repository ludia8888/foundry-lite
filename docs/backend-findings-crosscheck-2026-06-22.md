## CAS, Temporal, Saga, DLQ/DRQ의 관계

현재 코드에 맞춰 정리하면 다음과 같다.

- **Temporal**: 긴 작업을 잊지 않고 다시 실행해 주는 오케스트레이터다. 예를 들어 connector sync workflow를 시작하고, 실패하거나 오래 걸려도 상태를 추적한다.
- **Saga**: 외부 writeback처럼 DB 밖에서 이미 벌어진 일을 local DB와 맞추고, 실패하면 보상 또는 operator reconciliation으로 이어가는 패턴이다.
- **DLQ/DRQ**: 실패했거나 재처리가 필요한 이벤트와 레코드를 보관하는 장소이자 replay 경계다.
- **CAS**: 위 세 영역의 상태 변경이 서로 덮어쓰지 못하게 하는 잠금 없는 안전핀이다. 예를 들어 `RUNNING -> SUCCEEDED`와 `RUNNING -> FAILED`가 동시에 오면 둘 중 하나만 이겨야 한다.

즉 CAS는 Temporal, Saga, DLQ/DRQ를 대체하지 않는다. 대신 이들이 DB 상태를 바꾸는 모든 지점에서 "현재 상태가 내가 예상한 상태일 때만 다음 상태로 바꾼다"를 강제해야 한다.

## 핵심 결론

1. #49의 CAS 공통화는 실제로 의미가 있다. `status_cas.py`, `state_transitions.py`, repository별 CAS transition 사용이 들어와서 action, transform, materialization, index, ontology, DLQ, outbox, workflow, dataset transaction의 terminal race 위험이 줄었다.
2. 그러나 CAS coverage가 "모든 경쟁 상태를 자동으로 닫았다"는 뜻은 아니다. cleanup-before-claim, restore fence, cursor signing 같은 비상태 컬럼/외부 경계 문제는 여전히 남아 있다.
3. 현재 production multi-tenant 판단은 여전히 **NO-GO**에 가깝다. 로컬/개발용 MVP로는 강하지만, tenant isolation과 운영 복구 계약을 약속하려면 남은 partially-fixed 항목을 release gate로 승격해야 한다.

## 우선순위 권고

### 1차: CAS를 "쓴다"에서 "강제한다"로 올리기

- direct `status = ...` SQLAlchemy update를 금지하는 static gate 추가
- 모든 terminal transition에 allowed-current-state 목록을 선언
- affected row `0`일 때 `conflict`, `idempotent terminal replay`, `not found`를 구분
- cleanup-before-claim 경로를 claim-first state machine으로 재설계

### 2차: tenant namespace를 모든 외부 경계에 박기

- stream event tenant mismatch reject/quarantine
- workflow adapter lookup tenant-scoped port 변경
- search physical index/document id tenant hash 반영
- local connector snapshot key tenant 포함
- lineage/operations cursor tenant binding

### 3차: replay/retry의 재현성 고정

- action run에 action definition snapshot/revision 저장
- action idempotent terminal response snapshot 저장
- materialization definition/source snapshot revision 고정
- ontology activation과 object/search index contract atomic cutover

### 4차: production control plane 분리

- destructive schema reset을 production graph에서 물리적으로 제외
- restore mode를 audit 재구성이 아니라 `platform_control_state` row + lease/fencing token으로 강제
- CLI 운영 명령은 embedded demo admin이 아니라 HTTP/auth 경계를 통과
- Alembic-only production schema ownership과 RLS force role 강화
